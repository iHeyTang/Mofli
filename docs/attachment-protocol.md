# 挂载协议设计草案

状态：待实施。本文不表示运行时已支持挂载。

## 目标与现状

Core 定义与组合协议；骨架解释身体并提供动态绑定；部件解释自身外观与局部运动；皮肤提供默认搭配数据；宿主允许覆盖搭配。一个部件可消费多个挂载位置，一对耳朵是一次安装的一个实例。

当前 Frame.anchors: Point[] 用于调试，无语义、朝向或可见性；保留兼容，不复用为新协议。猫头私有 attachmentSurface/attachmentPoints 可作为迁移来源，但不能把轮廓数组索引暴露为公共约定。Frame.shapes 目前是平铺绘制序列；公共绘制插槽与资源隔离必须一起实施。

## 包依赖

- @mofli/core：协议类型、校验、部件注册与实例生命周期、组合器、资源命名空间、渲染。
- @mofli/rig-* -> core：声明挂载契约，输出动态挂载帧。
- @mofli/attachment-* -> core：声明所需契约，生成自己的图形。无需依赖具体骨架或皮肤。
- @mofli/skin-* -> 对应 rig：可存储部件 ID 与默认配置，不在可序列化皮肤中嵌入函数或动态导入路径。
- Studio / 宿主：显式导入并注册部件实现，解析皮肤引用，维护最终穿戴清单。

缺失注册实现需报告错误，不能根据 JSON 自动下载或执行代码。部件与骨架一样是受信任可执行代码，不宣称沙箱隔离。

## 静态契约与动态帧分开

Rig.mounts 声明稳定 ID、契约版本、能力类型、组成员、绘制插槽及占用策略。Frame.mounts 用同一 ID 输出当前绑定。能力兼容性在安装时检查，位置在每帧更新。

位置按角色身体语义命名，左右以角色自身为准。初期仅提供：

- head.crown：头顶中央的 frame 能力。
- head.upper.pair：左右上侧的 connection 能力，固定成员 left/right。
- head.lower.front：头部下缘前方的 frame 能力，用于领结；不假称当前骨架有颈部。

forehead、cheeks 等在实际需要时增加。组是多个绑定的容器，不是独立几何类型；单个组件也可同时声明多个契约需求。

## 绑定能力

1. frame：局部坐标系。输出 Affine2D、局部参考尺寸、visibility、深度排序信息。matrix 将归一化部件坐标映射到 Frame 坐标，尺寸包含在矩阵中，避免再重复乘一次缩放。
2. connection：在 frame 基础上增加有稳定参数方向的连接曲线、内侧覆盖带。耳根按曲线变形，根部向覆盖带延伸以消除接缝；不能只固定中心点。曲线点数和顺序在同一契约生命周期内固定。
3. surface：后续增加固定拓扑的 UV 网格与身体裁切资源，用于贴花。matrix 不足以表达非刚性表面变形。现有 markings 先保留，验证迁移后再统一。
4. envelope：后续提供角色中心、轮廓/范围和前后绘制区域，用于环绕效果；它不是真实三维深度模型。

各类数据使用带 kind 的联合类型。部件明确声明所需能力，不允许依靠一个可选字段堆成的对象猜测行为。

## 部件协议示意

```ts
interface AttachmentDefinition {
  id: string;
  version: 1;
  requires: Record<string, MountRequirement>;
  // 先校验配置与兼容性，昂贵绑定只在这里做。
  prepare(input: AttachmentSetup): AttachmentBinding;
  // 确定性时间输入；没有 DOM，也不能修改骨架帧。
  sample(input: AttachmentSample): AttachmentOutput;
}
```

以上类型名为设计示意，尚未加入公共导出。

一对耳朵的 requires 只声明一次 head.upper.pair，要求 left/right 都具有 connection 能力。内部可左右独立抖动或协同压耳。动作读取骨架公开的有界语义信号（例如 alertness、compression），不读取 Bloub 状态 ID、皮肤名称或轮廓点号。未知可选信号回退到约定中性值；必要信号缺失时判为不兼容。

帽子可同时输出帽冠与帽檐两个绘制部分；它们仍属于同一安装实例。

## 遮挡、连接与顺序

骨架公开语义绘制插槽，如 head.behind、head.overlay、face.overlay，并在自身图形序列中解析到具体位置。部件不引用 ink-body 等内部 ID。Core 根据插槽、局部深度与稳定实例顺序合成最终平铺 Shape[]。

部件输出的图形和资源均加实例命名空间。骨架若提供裁切，仅通过只读资源句柄引用，组合器负责重写；不允许部件覆盖宿主资源。不能仅靠一个 z 数值宣称解决所有遮挡。

connection 首期只支持同色轮廓重叠接合：部件根部位于宿主填充下方，连接曲线及覆盖带由骨架提供。若不同材质需要无缝边界、统一描边或布尔轮廓合并，必须另外提供 joint-fill 能力；普通 connection 不能承诺这些效果。猫耳迁移前必须验证全部状态，不能先删除现有集成轮廓。

占用按契约/区域定义：耳朵默认独占对应连接组；帽子与耳朵有潜在交叠，只有明示兼容的组合才开放共存。挂点兼容不等于不同饰品之间永不穿插。

## 动画与生命周期

安装后，挂载 ID 与组成员不随状态消失；变成符号时输出 visibility=0，并保留有效变换。骨架负责随其状态过渡连续计算 matrix、连接曲线和 visibility，恢复头部时同样平滑返回。不能由部件看到感叹号后自行猜测位置。

优先在骨架完成姿态混合后采样挂载数据，再让部件生成图形。Core 的帧级混合路径也必须处理挂载帧：旋转走最短弧，曲线按契约对应点混合，不直接混合任意矩阵导致塌缩；拓扑不兼容时，整套宿主与附属部件一同退场/入场，不能让部件跳到下一帧。

局部摆动使用统一 time、宿主公开运动量及 reducedMotion，必须可重放；不创建部件自己的 requestAnimationFrame。切换皮肤时重做兼容性检查；不兼容部件显示原因并卸载，不静默挂到其他位置。

## 皮肤与运行时搭配

皮肤可选 defaultAttachments 保存 attachment ID、契约版本范围和纯数据配置。宿主显式注册实现，并以运行时 overrides 合并/替换默认搭配。导出时区分皮肤默认配置与用户当前穿戴。一个部件可创建多个实例，但每个实例有唯一 ID，互不共享可变状态。

## 落地顺序与验收

1. Core 增加契约、frame/connection 数据、公共绘制插槽与注册组合器；现有无部件宠物输出不变。
2. Bloub 与猫头输出 crown、upper.pair、lower.front；Studio 增加可选挂载调试叠加图。
3. 一个帽子包、一个领结包在两个骨架复用；Studio 支持穿戴、卸下和兼容性提示。
4. 猫耳作为一个双侧组件试迁移，先与现有猫头并排验证连接和动作，再决定是否替换集成实现。
5. 有实际贴花/光环需求后扩展 surface/envelope。

必须覆盖：鼠标极值、左右转头与俯仰、参数极值、头部到符号的往返与中途打断、资源实例隔离、重放一致性、reducedMotion、冲突与缺失依赖错误、无部件回归；视觉验收包含耳根接缝、帽檐遮挡及桌面/移动端的 Studio 预览。

## 第一阶段已实现（2026-09-09）

已实现 `Rig.mounts`、`Frame.mounts/slots`、`composeAttachments`，以及两个只依赖 Core 的独立私有包 `@mofli/attachment-hat`、`@mofli/attachment-bow`。Bloub 和猫头提供 `head.crown` 与 `head.lower.front`。Studio 顶部饰品开关使用同一公共组合器；不佩戴时直接返回原 Frame。

当前协议刻意限定为 frame v1、纯 Shape 图形和骨架声明的绘制插槽，不支持部件资源、局部动画生命周期或任意曲面。挂载矩阵由真实当前轮廓的射线交点生成，参考尺寸包含在矩阵内；左右旋转使用头部 roll。它是轮廓绑定的二维近似，不是真实三维帽子透视。符号状态的挂载可见性随骨架姿态一起混合；frame 级混合也保留挂载数据。组合器检查重复实例、占用冲突、缺失挂载、无效数值，并为图形加实例前缀。

尚未实现：connection/upper.pair、耳根迁移、皮肤默认穿戴序列化、部件注册表、表面贴图及多层复杂遮挡。这些接口不以占位实现对外宣称支持。现有猫耳保持原实现；第一版帽子仅用一个 head.overlay 层，不能代表复杂帽檐遮挡已完成。

宿主调用示例：

```ts
import {composeAttachments} from '@mofli/core';
import {hat} from '@mofli/attachment-hat';
import {bow} from '@mofli/attachment-bow';
const frame = composeAttachments(engine.sample(time), [
  {id: 'my-hat', attachment: hat},
  {id: 'my-bow', attachment: bow},
]);
renderer.render(frame);
```

### 挂载朝向修正

frame 挂载现在接收完整的 yaw/pitch/roll（弧度），将局部横轴、纵轴一起投影；不再仅用 roll 旋转平面。头顶与下缘使用不同的正向深度偏移，使侧转时位置同步移动。姿态由骨架最终 gaze 提供，鼠标注视和状态动作共用此通道。帧级混合保留投影矩阵的剪切分量，端点不会被重新正交化。

这仍是平面部件的二维半投影：帽冠、帽檐尚无分面的真实三维几何或背面遮挡，不能表现完整绕头旋转。

### 统一头部空间与立体帽子（替代上一节的轮廓偏移算法）

两个骨架现在使用 `headMounts`，输入明确的头部中心、参考半径、顶部高度、当前底边和最终 gaze；朝向直接复用五官的 `spherical-face.headBasis`（度），避免额外 Euler 实现改变旋转顺序或俯仰符号。头顶安装点在头部局部空间固定，帽檐与顶部浅层相交；不再沿屏幕轮廓追逐一个点。原 `contourMounts` 保留兼容，但不再用于内置骨架。

frame 挂载可附带 volume 基底。部件声明 volume:true 后，必须有该能力；部件通过只读 project 回调将局部三维点投影为图形。帽子分为帽冠、帽顶、帽带、帽檐及厚度面，内部按深度排序，仍输出 SVG；领结不声明体积能力。

`head.lower.front` 在本次原型中明确为头下方宿主相对位置：跟随中心、尺寸、底边与状态可见性，不跟随五官的 yaw/pitch/roll。它不是下颌贴花，也不是有颈部骨架的领口。

限制：头部仍是二维轮廓模型，帽子使用正交投影与分面排序；尚无通用饰品—身体深度缓冲或复杂穿插裁切。不能把该实现称作完整三维场景。局部空间混合会重新正交化体积基底，避免在姿态切换时体积被剪切。

### 帽子遮挡修正

帽子按投影后面的朝向剔除背面；帽檐使用分段环形上表面、下表面及厚度边缘，不再用一整个圆盘的平均深度决定绘制顺序。部件可为每个图形选择骨架提供的 head.behind/head.overlay 插槽。投影携带安装原点的相机深度，位于头部中心平面后方的面在头部之前绘制，由实际二维身体轮廓遮挡。

该方式修复背面帽带透出及整顶帽子压在身体前方的问题，但前后分层仍按小面片的中心深度判断，不是逐像素深度缓冲。对任意复杂穿插装备仍不能承诺准确遮挡。

## 当前采用的路线：外置、不重叠（取代上述穿插遮挡实验）

内置挂载现在提供 clearance：实际主体 SVG 曲线的控制点包围范围、向外方向、间距及最大位移。部件必须提供完整外形的 footprint。Core 将 footprint 投影到画面，沿外侧方向平移，使主体与部件分别位于同一条分隔线的两侧。控制点凸包包住所有 Bezier 曲线；帽子的边界采用实际网格顶点，领结采用包住路径控制点的区域。保留间距以覆盖描边及舍入误差。

此算法是保守分离，不追求凹陷处嵌入。猫耳同样属于主体范围，帽子可能位于两耳上方。帽子内部仍可使用局部体积投影与背面剔除，但不再与头部计算穿插深度或分割遮挡。旧曲面裁切试验已从运行路径移除。领结固定在头下方。最大位移预算最后 20% 内逐渐隐藏，避免饰品无限漂移；隐藏前仍完整避让，不能靠夹紧位移容忍穿模。

范围：主体轮廓与已声明完整 footprint 的饰品。暂不保证多个饰品之间、通知气泡或粒子与饰品之间的避让；不支持深戴帽子、嵌入身体或包覆面具。通用新部件必须准确申报外形，不能只提供挂载中心点。

验证：两个骨架、五款皮肤、14 个状态、五个视线方向、符号切换过程，检查所有可见饰品图形顶点/控制点均在身体分隔线外侧。该数值验证辅以 Studio 上下转头、猫头及移动端截图。

### 领结朝向补齐

在外置避让方案下，head.lower.front 保留头下方的位置，但其局部横轴/纵轴使用与五官相同的 headBasis。因此领结随 yaw/pitch/roll 缩短、倾斜；底部安全位置和投影姿态分开处理。完整 footprint 在投影后参与避让，不能因为旋转而穿入身体。此修正取代此前“领结不跟随任何头部朝向”的临时约定；领结仍是平面图案的正交投影。

### 领结位置与朝向共用局部空间

领结挂载原点现在由头部局部“下方＋前方”位置投影得到，而非固定在画面下方中央。左右转头、俯仰、侧倾同时改变位置与基底。避让方向跟随该位置朝外，但始终保留向下分量；完整饰品再经支持平面分离，因此不会随位置投影进入主体。这个规则取代上一版只改变基底、不改变位置的实现。

## 当前生效约定：部件自行设计空间关系（取代外置避让方案）

已删除 Core 的 clearance、footprint、separateFootprint 与控制点避让计算，骨架也不再输出避让边界。组合器严格使用挂载矩阵/体积坐标，不自动平移或因位移预算隐藏部件。可见性仅跟随骨架状态。

领结是固定在下前方挂载位置的前景平面，允许与主体图形重叠，使用同一头部坐标系投影位置和基底。帽子包自行将模型沿头部局部负 Y 方向抬高 0.45 个参考半径，形成悬浮帽饰；这个安装偏移不影响其他部件。Core 不再承诺或计算通用饰品与主体不重叠，新的饰品需自行设计尺寸、安装偏移和适用角度。
