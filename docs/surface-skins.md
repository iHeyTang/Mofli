# 受约束的表面皮肤

皮肤声明画什么，骨架决定附着、投影、变形、遮挡和状态可见性。无需为每个动作提供一套图案。

## 当前协议

Skin.markings 是最多 8 个花纹，每个包含唯一 id、骨架支持的 slot、六位十六进制 color、0–1 opacity 和 32 个局部边界 points。点的 x/y 必须在 -1–1 内，按边界顺序排列；作者应使用简单、不自交的轮廓。固定采样数支持换肤时相同花纹的轮廓插值。验证器检查数据范围和插槽，不负责自动美化轮廓。

Skin.variants 保存骨架支持的绘制样式选择。它不替换动画代码或表达式。未知插槽、样式、SVG 字符串和额外字段都会被拒绝。

骨架通过 surfaces 与 variants 声明支持能力。核心只验证这些声明，不假设所有角色都是球体。具体投影由骨架执行；没有声明表面能力的骨架不能加载带花纹的皮肤。

## 猫头实现

目前开放 forehead、leftCheek、rightCheek 三个局部表面。骨架为其定义位置和范围，采用与眼睛共享的朝向基底投影，并读取当前轮廓的径向缩放、压扁、位移。背面边界在投影前裁切，身体/眼睛/通知点共用遮罩，花纹放在身体之上、装饰之前。

符号状态沿用骨架的 headTurn 可见性权重，思考点、感叹号、休眠点和爆散会收起花纹；头部状态随权重保留或减弱。皮肤不包含状态名称或判断分支。

variants.eyes 支持 capsule 与 oval。两者继续使用同一组骨架计算的尺寸、透视矩阵、眼睑缩放和透明度，改变的是画法。样式枚举切换本身是离散选择，不承诺不同样式之间连续形变。

Patches 皮肤只声明两个局部色块和 oval 眼睛，没有动作实现。工作台可选择它，exportSkin / 保存皮肤 JSON 会保留花纹、样式、配色和当前几何值。

## 边界

当前是猫头的 2.5D 绑定方案，不是通用三维 UV 或布料模拟。尚未开放耳内表面、任意纹理图片、毛发材质、任意五官或外部 SVG 注入。新能力需要骨架明确实现，不会自动承诺未知结构的适配。Bloub 原始渲染保持不变。
